Colour coding · the rulebook

Every colour gets exactly one job

Colour coding works when a colour always means the same thing. The same five meanings run through the plan illustrations and the page UI, so visitors learn the language without noticing.

Accessibility rule baked in: tinted fills carry the zone colour, but outlines and text use the darker contrast-safe version (orange #C2540A, cyan #0369A1, green #15803D). Every zone is also named in text and in a legend, so nothing depends on colour alone (WCAG 1.4.1).

Option set 1 · colour coding of the plan

Three ways to colour the same plan

Same geometry, same illustration style. Only the colour logic changes. Hover or tab to a legend item to see that zone isolated.

Colour 1 · Calm Cyan Safest

  • Two meanings only: orange = entrances, cyan = coverage
  • Quietest, most “corporate”
  • Less information per glance

Colour 2 · Zone Coded Most informative

  • Four zone types, four colours, one legend
  • Shows that YONAM plans entrances, outdoors, common areas and recording separately
  • Still under about 4% of the page area for warm colours

Colour 3 · Mono Navy Strict

  • All navy, with only the entrances in orange
  • Most restrained, closest to the PRD’s navy-first brief
  • Reads as architectural drawing, least friendly for homeowners
Option set 2 · illustration style

Three drawing styles

All three are plain inline SVG, a few KB each, no images to load. They are labelled “Illustrative · not to scale” so nobody mistakes them for a real YONAM plan. Shown in the Zone Coded colours.

Style 1 · Plan view

  • Top-down floor plan with soft filled zones
  • Clearest for “entrances, parking, common areas”
  • Easiest to animate and to keep readable on mobile

Style 2 · Line blueprint

  • Thin technical linework, dashed coverage
  • Most “engineer” feel, matches the grid background
  • Lighter on screen, slightly less friendly

Style 3 · Isometric Most impressive

  • A building in perspective, coverage on the ground
  • Most visual impact, best as a hero image
  • Harder to read small, needs most craft to extend
Option set 3 · animation

Four small motions

Each one is CSS only. No animation library, no scroll-triggered effects. Each runs for about 5 seconds at most, then rests, because moving content that never stops fails accessibility rules. Hover a plan to replay it.

Motion 1 · Scanning Recommended

What
Coverage cones sweep ±5° around each camera
Timing
2.4 s, 2 cycles, ease-in-out
Meaning
“Cameras are watching”, without a single claim
Cost
transform only, GPU friendly

Motion 2 · Drawing in Recommended

What

1.8 s, once, on first view
Meaning

Cost

Motion 3 · Camera pulse

What
A soft ring expands from each camera point
Timing
2.4 s, 2 cycles, ease-out
Meaning
“Live”, can feel like a recording indicator
Cost
transform and opacity

Always on, no motion: hovering or focusing a legend item isolates that zone on the plan. It is interaction, not decoration, and it works on a tap as well.

Rules that apply to whatever you pick

Honesty

  • Every plan is captioned “Illustrative · not to scale”.
  • No real customer plans or property layouts without permission.
  • Camera counts and positions in drawings are examples, never an offer or a quote.

Motion

  • CSS only, no libraries. Under 2 KB of added script.
  • Every animation ends within about 5 seconds, then rests.
  • Respects the “reduce motion” setting: everything shows in its final state.
  • Motion only on the hero, the planning section and the process timeline.

Performance

  • Illustrations are inline SVG, each about 3 to 6 KB.
  • No layout shift: drawings have fixed aspect ratios.
  • Animates transform and opacity wherever possible.

Accessibility

  • Each drawing has a text description, and a legend names every colour.
  • Contrast-safe darker outlines on all tinted zones.
  • Legend items are real buttons: keyboard and touch work, not hover only.
